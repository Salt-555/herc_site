# Agent Guide

Static browser animation site for Gaylord's Shop. No build step, no framework, no server-side file scanning.

## Architecture

### Data-Driven Design

The site uses three config arrays in `script.js` that drive all behavior:

**`SCREENS[]`** -- background video layers (TV, Game Cabinet, etc.). Each entry defines:
- `id`, `elementId` -- screen name and DOM element
- `channels` -- array of WebM paths (populated from manifest.js globals)
- `baseSize` -- coordinate space (1024 or 1440)
- `corners` -- quadrilateral for positioning (topLeft, topRight, bottomLeft, bottomRight)

One set of generic functions (`playRandomChannel`, `updateScreenPosition`) handles all screens. Event listeners are wired automatically via `forEach`.

**`HOTSPOTS[]`** -- clickable zones. Each entry defines:
- `elementId` -- DOM element
- `left`, `top`, `width`, `height` -- rectangle in 1024x1024 space
- `pathway` -- key into `CONFIG.pathways` (array of clip paths; random one chosen on click)

Click handlers are wired automatically from config. `hideHotspots()`/`showHotspots()` iterate the array.

**`CONFIG`** -- idle clips, pathway clips, timing:
- `idleClips` -- array of `{ id, src }` for random idle animations
- `pathways` -- object mapping pathway names to arrays of clip paths
- `idleDelay` -- min/max milliseconds between idle clips
- `baseClip` -- the looping alpha-masked idle WebM
- `wakeClip` -- first-click startup animation (`wakes_up.webm`)

### Adding a New Background Screen

1. Add entry to `SCREENS[]` in `script.js` with corners, baseSize, and `hotspotId` (links to the hotspot that controls audio hover)
2. Add `<video id="your-id" class="scene-media your-class" muted playsinline loop preload="auto">` in `index.html`
3. Add CSS class (`.your-class`) with `width:0; height:0; object-fit:fill; transform:none; z-index:1; opacity:0;` and a `clip-path` polygon computed from the corners
4. Create `Media/Your_Dir/manifest.js` exporting `window.YOUR_CHANNELS = [...]`
5. Load the manifest in `index.html` before `script.js`
6. Add the clip-path polygon to `screens.json` for reference
7. Optionally create a processing script in `scripts/`

No new functions or event listeners needed.

### Adding a New Hotspot

1. Add entry to `HOTSPOTS[]` with coordinates and `pathway` key
2. Add `<div id="your-id" class="hotspot">` in `index.html`
3. Add the pathway key to `CONFIG.pathways` as an array of clip paths

No manual click handler wiring needed.

## Layer Stack

```text
z1    tv-player              Clipped TV background video (positioned via JS, clip-path in CSS)
z1    game-cabinet-player    Clipped game cabinet background video (same z-level, separate position)
z2    idle-image             JPG fallback (1024x1024, always present for sizing/sceneRect)
z3    idle-base-player       Looping base WebM with alpha holes for TV + cabinet
z3    arcade-canvas          Interactive Asteroach canvas, visible only after Game Cabinet zoom ends
z3    tv-vhs-menu            VHS-style Hercules Recycled 2.0 buy/rent menu after TV zoom ends
z4    animation-player       Foreground idle/pathway clips (VP9 alpha)
---   bg-music-player        <audio> element — continuous background music (no visual layer)
z100  smoke-canvas           Smoke particle overlay
z150  hotspots               Invisible click zones (also hover zones for audio ducking)
z200  back-button            Pathway-only Go Back button
z210  arcade-controls        Context-sensitive cabinet game control guide
z9999 eye-overlay            Opening/closing eyelids
```

TV and Game Cabinet videos sit behind the alpha-masked base/foreground WebMs. The alpha holes in the character WebMs let the background layers show through.

## Animation Model

States in `script.js`:

```text
WAITING_WAKE         Startup state: wake clip held on first frame until first click
PLAYING_WAKE         Wake clip plays once, then transitions to IDLE
IDLE                 Base loop playing, waiting for random idle clip timer. Next clip preloaded.
LOADING_IDLE_CLIP    Idle clip loading (canplay triggers playback)
PLAYING_IDLE_CLIP    Idle clip playing over base (ends -> return to IDLE)
PATHWAY              Pathway clip playing (pauses on final frame, back button visible)
```

On initial page load, `wakes_up.webm` is loaded into `animation-player`, held on its first frame, and hotspots/idle scheduling are disabled. The first click anywhere on the page starts the wake clip and unlocks audio. When the wake clip ends, `startBaseIdleLoop()` and `scheduleNextIdleClip()` take over and the normal idle state begins.

Idle clips start/end on the same base pose. Randomly chosen every 5-15s. The next idle clip is preloaded into a detached `<video>` element during the idle wait period for instant playback.

Pathway clips are triggered by hotspot clicks. Go Back closes eyelids, resets state to IDLE (no page reload), and re-opens eyelids via CSS animation restart.

### Game Cabinet Arcade

Clicking the Game Cabinet hotspot plays `Game_Zoom1.webm` as a special `gameZooms` pathway. During the first 25% of the zoom, the idle TV and Game Cabinet media remain visible for continuity. After 25%, those idle screen layers and the base idle layer are hidden/paused so the zoom transparency does not reveal the idle scene recursively.

When the zoom clip ends, `arcade-canvas` becomes active behind the transparent cabinet screen and `arcade-controls` appears beside the scene. `arcade.js` owns the standalone interactive arcade system:
- `createCabinetArcade({ canvas, guide })` returns `showMenu()`, `hide()`, and `setAudioState()` methods used by `script.js`
- Current game: Asteroach, an Asteroids-style crude vector/pixel roach game
- Controls: Enter/click starts, WASD/arrows move, Space/click fires, mouse aims, Esc returns to the in-cabinet menu
- Go Back exits cabinet mode completely and returns to the normal idle state
- SFX are generated with Web Audio chip sounds and respect the shared mute/master volume controls

`arcade.js` renders gameplay to an offscreen canvas first, then draws it to the visible canvas in warped strips for CRT/barrel distortion. The visible arcade canvas is positioned by `CABINET_ARCADE_SCREEN` in `script.js` using 1440x1440 `Game_Zoom1` coordinates. CSS adds a perspective/skew transform only; do not reintroduce `clip-path` cropping for the arcade surface unless explicitly requested.

### TV Zoom VHS Menu

Clicking the TV hotspot plays `TV_zoom2.webm` as the `tvZooms` pathway. Like the Game Cabinet zoom, the idle TV and Game Cabinet media remain visible for the first 25% of the zoom for continuity. After 25%, those idle screen layers and the base idle layer are hidden/paused so the transparent TV close-up does not reveal recursive idle content.

When the TV zoom clip ends, `tv-vhs-menu` becomes active behind the transparent TV screen. It shows a VHS-style menu for **HERCULES RECYCLED 2.0** with a buy/rent prompt linking to the Amazon Prime Video listing:

```text
https://www.amazon.com/Hercules-Recycled-2-0-Steve-Reeves/dp/B08DSS9TKD
```

`tv-vhs-menu` is positioned by `TV_VHS_SCREEN` in `script.js` using 1440x1440 `TV_zoom2` coordinates derived from `Media/Videos_Gaylords_Shop/TV zoom in mask.png`. Go Back exits TV zoom mode completely and returns to the normal idle state.

## Sound Engine

The site uses a three-layer audio mixing system with smooth cross-fading:

### Audio Layers

| Layer | Default Volume | When Hovering a Screen |
|-------|---------------|----------------------|
| BG Music | `0.5` (`bgDefault`) | Ducks to `0.15` (`bgDucked`) |
| Character clips (idle + pathway) | `1.0` (`charDefault`) | Ducks to `0.3` (`charDucked`) |
| TV video audio | `0` (silent) | Fades up to `0.8` (`screenFocused`) |
| Game Cabinet video audio | `0` (silent) | Fades up to `0.8` (`screenFocused`) |

All layer volumes are multiplied by `masterVolume` (controlled by the volume slider) and zeroed when muted.

### How It Works

- BG Music plays continuously via an `<audio id="bg-music-player">` element. Tracks rotate randomly (no consecutive repeats; single track loops).
- All screen `<video>` elements start muted and at volume 0 for autoplay compliance.
- On first user interaction, audio is unlocked: elements are unmuted and BG music begins.
- Hovering a hotspot triggers `setHoverTarget(screen)` which sets volume targets; `requestAnimationFrame` smoothly ramps volumes at `AUDIO_MIX.fadeSpeed` (default 4.0 units/sec = ~250ms for 0-to-1).
- Moving the mouse off any hotspot restores BG music and silences screen audio.
- Each `SCREENS[]` entry has a `hotspotId` linking it to its hover zone.

### `AUDIO_MIX` Config (in `script.js`)

```js
const AUDIO_MIX = {
    bgDefault:     0.5,   // BG music volume when idle
    bgDucked:      0.15,  // BG music volume when hovering a screen
    charDefault:   1.0,   // Character clip volume when idle
    charDucked:    0.3,   // Character clip volume when hovering a screen
    screenFocused: 0.8,   // Screen volume when hovered
    fadeSpeed:     4.0    // Volume ramp speed (units/sec)
};
```

### Adding Background Music

1. Drop audio files (`.mp3`, `.ogg`, `.webm`, `.wav`, `.m4a`, `.aac`, `.flac`, `.opus`) into `Media/BG_Music/`
2. Run `scripts/build-bg-music-manifest.sh` from the project root — it scans the folder and regenerates `manifest.js` automatically
3. Single track loops automatically; multiple tracks rotate randomly

No manual manifest editing needed. Just add/remove files and re-run the script.

### Adding Audio to a New Screen

When adding a new `SCREENS[]` entry, include `hotspotId` pointing to the corresponding hotspot element ID. The sound engine will automatically wire hover listeners and manage volume fading. No additional audio code needed.

## Alpha Mask Pipeline (Two-Step)

All character WebMs are generated from source MP4s using `scripts/mask-gaylord-videos.sh`:

**Step 1** -- Extract RGBA PNG frames with mask alpha applied:
```bash
ffmpeg -y -i video.mp4 -loop 1 -t $duration -i TVMask.png \
  -filter_complex "[1:v]scale=WxH:flags=lanczos,format=rgba[mask];[0:v]format=rgba[vid];[vid][mask]blend=all_mode=and:all_opacity=1:all_expr='A*B/255',format=rgba[out]" \
  -map "[out]" -t $duration frames/frame_%05d.png
```

**Step 2** -- Encode PNGs to VP9 alpha WebM:
```bash
ffmpeg -y -framerate $fps -i frames/frame_%05d.png \
  -c:v libvpx-vp9 -pix_fmt yuva420p -auto-alt-ref 0 -crf 28 -b:v 0 -an output.webm
```

Key facts:
- Single-pass `alphamerge` does NOT work -- produces opaque pixels despite correct metadata.
- `-t "$duration"` required on both mask input and output (mask `-loop 1` creates infinite stream).
- `ffprobe` reports `pix_fmt=yuv420p` even when alpha IS present. Check `TAG:alpha_mode=1` instead.
- For still images (Idle_photo.jpg), first create an MP4 (`ffmpeg -loop 1 -framerate 24 -t 5 -i photo.jpg ...`), then run through the mask script.

Generate all processed WebMs:
```bash
scripts/mask-gaylord-videos.sh          # Skip existing
FORCE=1 scripts/mask-gaylord-videos.sh  # Rebuild all
scripts/mask-gaylord-videos.sh --dry-run
```

## Adding Background Clips

### TV (BG_TV)

Process source footage and add to manifest:

```bash
scripts/process-bg-tv.sh input.mp4 Media/BG_TV/output.webm [duration] [start-time]
```

Then add to `Media/BG_TV/manifest.js`:
```js
window.BG_TV_CHANNELS = [
    'Media/BG_TV/notld_tv_01.webm',
    'Media/BG_TV/new_clip.webm'
];
```

### Game Cabinet

Drop source MP4s into `Media/Game_Cabinet/`, then run:

```bash
scripts/process-game-cabinet.sh
```

This batch-processes all MP4s to keystoned VP9 WebMs (130x118, 12fps). Then add to `Media/Game_Cabinet/manifest.js`:
```js
window.GAME_CABINET_CHANNELS = [
    'Media/Game_Cabinet/clip_name.webm'
];
```

Both systems: single clip loops, multiple clips rotate randomly without consecutive repeats.

## Adding Idle Clips

Place source MP4 in `Media/Videos_Gaylords_Shop/`, run `scripts/mask-gaylord-videos.sh`, then add to `CONFIG.idleClips` in `script.js`:

```js
{ id: 'new-idle', src: `${MEDIA_PATH}new_idle.webm` }
```

All idle clips must be VP9 alpha WebMs so TV/cabinet layers show through.

## Adding Pathways

1. Add clip array under `CONFIG.pathways` in `script.js`:
   ```js
   pathways: {
       myNewPath: [`${MEDIA_PATH}my_clip.webm`]
   }
   ```
2. Add a `HOTSPOTS[]` entry pointing to the pathway key:
   ```js
   { elementId: 'my-hotspot', left: X, top: Y, width: W, height: H, pathway: 'myNewPath' }
   ```
3. Add `<div id="my-hotspot" class="hotspot">` in `index.html`.

Click handler is wired automatically. No manual function calls needed.

## Alpha Verification

Check alpha metadata:
```bash
ffprobe -v error -select_streams v:0 \
  -show_entries stream_tags=alpha_mode -of default file.webm
```
Expected: `TAG:alpha_mode=1`

Decode and verify actual transparent pixels:
```bash
ffmpeg -y -c:v libvpx-vp9 -i file.webm -frames:v 1 -update 1 -pix_fmt rgba /tmp/decoded.png
magick /tmp/decoded.png -crop 1x1+300+600 txt:-
```
Transparent area should show `alpha=0`. Do NOT trust `ffprobe pix_fmt` alone.
